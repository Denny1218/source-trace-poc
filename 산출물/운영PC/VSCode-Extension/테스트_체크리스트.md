# VS Code Extension 테스트 체크리스트

**대상 패키지**: `source-trace-vscode-0.5.5.vsix`

## 설치

- [ ] `source-trace-vscode-0.5.5.vsix`를 VS Code에 설치 (Install from VSIX)
- [ ] Extensions 목록에 `장비 변경 이력 조회 (Source Trace)` 표시
- [ ] Extensions 목록/상세에 ATEC Mobility 워드마크형 아이콘 표시
- [ ] (이전 버전 사용 중이었다면) 0.5.5로 재설치 완료
- [ ] 명령 팔레트에 `Source Trace: 함수 변경 이력 조회`와 `Source Trace: 선택 코드 변경 근거 조회`가
      **별도 명령**으로 표시됨 (`Source Trace: 장비 변경 이력 조회` 옛 명령은 팔레트에 없음)

## 최초 설정

- [ ] `F1` → `Source Trace: 서버 및 장비 설정` 실행
- [ ] 서버 주소 입력 (예: `http://192.168.155.89:8010`)
- [ ] 서버 연결 성공 확인
- [ ] 장비 목록 Quick Pick에서 장비 선택
- [ ] "Source Trace 설정 완료" 메시지 확인
- [ ] `보기 → Output → Source Trace`에서 설정 로그 확인

## 설정 (직접 입력 방식 대안)

- [ ] `sourceTrace.serverUrl` = `http://<서버IP>:8010`
- [ ] `sourceTrace.equipmentId` = 관리 화면에서 확인한 장비 ID (기본값 없음)
- [ ] `sourceTrace.useOllama` = `false` (기본)
- [ ] `sourceTrace.showDebug` = `false` (기본)

## 설정 명령 시나리오

- [ ] `Source Trace: 서버 및 장비 설정` → **서버 주소 InputBox** 표시 → 장비 Quick Pick → 설정 완료
- [ ] `Source Trace: 장비 변경` → **서버 주소 InputBox가 나오지 않음** → 연결 확인 후 장비 Quick Pick만 표시
- [ ] `Source Trace: 장비 변경`으로 다른 장비 선택 → 현재 Workspace의 장비만 변경됨
- [ ] Workspace A에서 장비 X 선택 후 Workspace B에서 장비 Y 선택 → A로 돌아오면 X 유지
- [ ] 서버 URL 미설정 상태에서 `장비 변경` → setup 유도 안내
- [ ] `Source Trace: 서버 연결 확인` → 연결 성공/실패 메시지 표시
- [ ] `Source Trace: 현재 설정 보기` → 서버·장비명·저장소 수 표시
- [ ] 서버 주소에 API 경로 포함 입력 (예: `/api/trace/report`) → 자동 제거 후 저장
- [ ] 서버 미연결 상태에서 분석 → "설정 시작" 버튼 표시 → 클릭 시 설정 마법사

## 장비 검증 시나리오

- [ ] 존재하지 않는 장비 ID 입력 → "장비 ID N을 서버에서 찾을 수 없습니다..." 오류 표시
- [ ] 올바른 장비 ID 입력 → Output에 `장비: <장비명>`, `장비 ID: N` 표시 후 분석 진행

## 선택 코드 변경 근거 조회 (v0.5.3 신규)

- [ ] `Fare/src/fare_calc.c` 등 소스 파일 열기
- [ ] 조건문 등 코드 **한 줄을 드래그로 선택** → 우클릭 → `Source Trace: 선택 코드 변경 근거 조회`
- [ ] 선택 없이(커서만 두고) 명령 실행 → 코드를 선택하라는 안내 표시, 분석이 실행되지 않음
- [ ] 공백만 선택 후 실행 → 동일하게 선택 안내 표시
- [ ] 결과 Markdown 제목이 `# 선택 코드 변경 근거`
- [ ] **이미 Commit된 코드**를 선택하면 `## 현재 라인의 Git 근거`에 실제 `git blame` Commit hash·작성자·날짜·Commit 메시지 표시
- [ ] 표시된 Commit이 해당 파일·라인의 **실제 blame 결과**와 일치함 (키워드 검색 1위 결과가 아님)
- [ ] **아직 Commit되지 않은 로컬 전용 코드**를 선택하면 과거 Commit을 보여주지 않고  
      「선택한 코드와 서버 Git 소스가 일치하지 않습니다」안내가 표시됨
- [ ] 한 줄의 **일부 문자열만** 선택해도 서버 revision과 일치하면 정상 blame 결과 표시
- [ ] `## 실제 변경 내용`에 선택 라인과 겹치는 Diff hunk(가능하면 변경 전/후 코드) 표시. 전체 파일 Diff는 미노출
- [ ] 변경 유형은 Diff로 확인된 경우에만 추가/수정/삭제 표시. 미확정이면 `변경 Commit 확인`
- [ ] `## line history`에 과거 변경 Commit 목록 표시 (추적 가능한 경우). 실패해도 blame 결과는 유지
- [ ] line history 추적이 제한되면 "코드 이동 또는 Git 추적 제한으로 완전하게 확인하지 못했습니다" 계열 문구 표시 (추측 금지)
- [ ] `## 관련 문서`에 **선택 코드와 직접 연결된 문서만** 표시. 함수 전체 문서를 강제 복사하지 않음
- [ ] 직접 연결 문서가 없으면 "관련 문서를 찾지 못했습니다." 표시
- [ ] 결과 하단에 "함수 전체 이력은 `함수 변경 이력 조회`에서 별도로 확인" 안내 표시, 함수 전체 lifecycle이 자동으로 붙지 않음
- [ ] 여러 줄(서로 다른 Commit 포함) 선택 시 Commit별로 행 범위가 구분되어 표시됨
- [ ] 함수 조회와 선택 조회의 파일 경로(`repo_relative_path`)·short hash(8자리)가 동일 기준
- [ ] Extension 설치 시 `sourceTrace.analyzeSelection` menu 미정의 `1 message` 경고가 없음
- [ ] Output에 `현재 라인 Commit: <hash>`, `line history 조회 완료` 또는 `line history 확인 제한`, `분석 완료` 로그 표시
- [ ] Output 및 결과 Markdown에 선택 코드 원문·전체 Diff·raw JSON·후보 score 전체가 노출되지 않음
- [ ] Remote-SSH(또는 로컬 절대경로)에서 조회 시 `선택한 파일이 장비 Git Repository 내부에서 확인되지 않았습니다`로 즉시 실패하지 않음
- [ ] 다중 Repo 장비에서도 Backend 공통 resolver가 현재 상대경로로 Repo를 결정함

## 함수 이력 · 문서 관계 (v0.5.3 / PROJECT_SPEC v2.6)

- [ ] 변경 상세에서 Commit 메시지와 `코드에서 확인`이 분리되고, 메시지가 Diff 사실로 중복되지 않음
- [ ] `관련 호출부가 함께 추가되었을 수 있습니다` 등 추측성 문장 미출력
- [ ] 관련 문서 접힘이 `관련 소스·함수 보기`이며 `### 연결 Commit` 미표시
- [ ] Commit 상세에 stage/reference 문서가 반복되지 않음 (Commit 직접만 가능)
- [ ] `## 관련 문서`에 함수 수준 관련 문서가 표시됨
- [ ] `변경 이력` 표가 날짜/Commit/변경 내용 3열
- [ ] Diff 확인 항목은 Diff+Commit 메시지 사실 기반 구체 설명. Message-only는 `(대상 함수 Diff 미확인)`
- [ ] 부모 미검증 최초 항목은 `최초 확인` 표현(새로 추가 단정 금지)
- [ ] 관련 함수/소스 목록이 길어도 현재 조회 대상이 원본에 있으면 표시되고 `외 N개`가 붙음
- [ ] 관련 함수 목록에 없는 문서에 "동일 함수가 명시" 문구가 나오지 않음
- [ ] Repo 매칭 실패 Output 원인이 서버 연결 안내와 분리됨 (remote URL / 등록 Repo / Git root)
- [ ] SSH·HTTPS·`.git` 표기 차이나도 동일 Repo로 매칭됨
- [ ] 함수 이력 조회 후 동일 파일에서 선택 코드 조회 시 Repo 재사용으로 blame까지 진입

## showDebug

- [ ] `showDebug=false` → 결과 Markdown에 `Extension debug` 문자열 없음
- [ ] `showDebug=true` → 결과 하단 접힌(`details`) Extension debug 표시
- [ ] Output Channel `Source Trace`에는 설정과 무관하게 debug 로그 유지

## Continue 연동 제거 회귀 확인 (0.2.0 이후 유지)

- [ ] 명령 팔레트에 `Continue` 관련 명령이 전혀 없음 (`Continue 설정 스니펫 생성` 등)
- [ ] `sourceTrace.continueProgress` / `sourceTrace.continueProgressDetail` 설정이
      Extension 설정 UI에 더 이상 표시되지 않음
- [ ] Output Channel에 Continue 요청 시작/완료/실패 로그가 표시되지 않음
- [ ] 기존 `settings.json`에 위 폐기 설정 값이 남아 있어도 Extension이 오류 없이 무시함
- [ ] Backend가 `/api/continue/trace`를 더 이상 제공하지 않음 (404)
- [ ] `함수 변경 이력 조회`는 `/api/trace/report`, `선택 코드 변경 근거 조회`는
      `/api/trace/selection`만 호출함 (두 API가 서로 대체되지 않음)
- [ ] 기존 명령(`서버 및 장비 설정` 등) 동작에 회귀 없음
- [ ] **일반 `Source Trace` Output Channel과 시작·완료 로그는 Continue 제거와 무관하게 정상 표시됨**
      (Continue 전용 Output만 없고, 일반 Output까지 사라지면 회귀임)
