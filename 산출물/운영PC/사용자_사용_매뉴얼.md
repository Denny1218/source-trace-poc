# Source Trace 사용자 사용 매뉴얼

이 문서는 **서버가 이미 설치·기동된 상태**에서, 사용자가 Web과 VS Code Extension으로
장비를 등록하고 변경 이력을 조회하는 **사용 절차**만 안내합니다.

서버 설치·오프라인 패키징·환경 점검은 다루지 않습니다.

---

## 전체 흐름 (한눈에)

```text
1) 브라우저로 Source Trace 접속
2) [장비 관리]에서 장비 등록
   ├─ 변경내역서 폴더(UNC) 등록 · 경로 확인
   └─ Git 주소(Repository) 등록 · 연결 확인 · 저장
3) [Git 변경 이력]에서 Git 동기화
4) (권장) [변경내역서 분석]에서 PPT 분석 1회 실행
5) [Source Trace 조회] 또는 VS Code Extension으로 변경 이력 조회
```

역할 구분:

| 구분 | 하는 일 |
|------|---------|
| 관리자/운영 담당 | Web에서 장비·Git·변경내역서 등록, Git 동기화, PPT 분석 |
| 개발자(사용자) | Web `Source Trace 조회` 또는 VS Code Extension으로 변경 이력 조회 |

한 사람이 모두 해도 됩니다. 아래는 순서대로 따라 하면 됩니다.

---

## 0. 사전 확인

시작 전에 아래만 확인합니다.

1. Source Trace 서버가 켜져 있다.
2. 관리자에게 **서버 주소**를 받았다. 예: `http://192.168.10.50:8010`
3. 본인 PC에서 서버 `8010` 포트에 접속 가능하다.
4. 변경내역서 폴더는 **네트워크 공유(UNC)** 경로이다.
   - 예: `\\파일서버\공유\장비명\변경내역서`
   - 본인 PC의 `C:\...` 로컬 폴더는 사용하지 않는다.
5. Git 주소(Yona 등) 또는 서버에서 접근 가능한 Local Git 경로를 알고 있다.

> 브라우저 주소창에 `localhost:8010`을 치면 **본인 PC**를 가리킵니다.  
> 반드시 관리자가 알려 준 **서버 IP**를 사용하세요.

---

## 1. 웹 접속

### 1-1. 브라우저로 열기

주소창에 입력:

```text
http://<서버IP>:8010
```

예:

```text
http://192.168.10.50:8010
```

또는 운영PC 폴더의 `open_browser.bat`을 실행합니다.  
(`server_host.txt`에 서버 IP가 들어 있어야 합니다.)

### 1-2. 화면 구성

상단(또는 좌측) 메뉴:

| 메뉴 | 용도 |
|------|------|
| 시스템 상태 | 서버·DB·Git 연결 상태 확인 |
| 장비 관리 | 장비 / 변경내역서 폴더 / Git 등록 |
| Git 변경 이력 | Git Commit 조회 · Git 동기화 |
| 변경내역서 분석 | PPT 변경내역서 분석 · 검색 |
| Source Trace 조회 | 함수 변경 이력 · 선택 코드 변경 근거 조회 |

먼저 **시스템 상태**에서 Backend·Database가 정상인지 확인한 뒤 **장비 관리**로 이동합니다.

---

## 2. 장비 등록 (Web)

### 2-1. 장비 추가

1. **장비 관리** 탭을 연다.
2. **장비 추가**를 누른다.
3. **장비명**을 입력한다. (예: `휴대용정산기`, `개집표기`)
4. **변경내역서 폴더**에 UNC 경로를 붙여넣는다.
   - Windows 탐색기에서 해당 네트워크 폴더를 연다.
   - 주소창의 경로를 복사해 붙여넣는다.
   - 예: `\\server\share\HHD200`
5. **경로 확인**을 누른다.
   - 성공: PPTX 개수 등이 표시된다.
   - 실패: 경로·공유 권한·서버 PC의 네트워크 접근을 확인한다.
6. (다음 절) Git Repository를 추가한다. **0개로 저장도 가능**하지만, 이력 조회를 하려면 반드시 등록한다.
7. **장비 저장**을 누른다.

저장 후 목록에 장비가 보이면 등록 완료입니다.

### 2-2. 변경내역서 폴더 주의사항

- **UNC만** 사용한다. (`\\서버\공유\...`)
- 운영 PC에만 있는 로컬 폴더는 서버가 읽을 수 없다.
- 폴더 안에 `.pptx` 변경내역서가 있어야 한다. (`.ppt`는 대상이 아님)
- 하위 폴더의 PPTX도 포함해 확인할 수 있다.

---

## 3. Git 주소 등록 (Web)

장비 추가/수정 화면의 **Git Repository** 영역에서 등록합니다.

### 3-1. Repository 추가

1. **+ Repository 추가**를 누른다.
2. Repository 이름(표시용)을 입력한다.
3. 유형을 선택한다.
   - **Remote**: Yona 등 원격 Git URL
   - **Local**: 서버 PC에서 접근 가능한 로컬 Git 경로
4. URL 또는 경로를 입력한다.
   - Remote 예: `http://사용자ID@서버주소:포트/프로젝트/저장소`
   - Yona URL은 **개발자가 쓰는 주소를 그대로** 붙여넣어도 된다.
     (URL에 들어 있는 Username은 서버 설정 계정이 우선 사용될 수 있다.)
5. **연결 확인**(Remote) 또는 **경로 확인**(Local)을 누른다.
6. **목록에 추가**를 누른다.
7. 장비 **저장**을 누른다.

저장 후 Repository 상태가 **Ready**인지 확인합니다.  
`Pending` / `Error`이면 연결·권한·URL을 다시 확인합니다.

### 3-2. 여러 Repository

한 장비에 Git 저장소가 여러 개면 Repository를 여러 건 추가할 수 있습니다.  
장비마다 소스 저장소가 다르면 **장비를 따로** 등록하는 편이 안전합니다.

---

## 4. Git 동기화 (Web)

장비를 등록했다고 해서 Commit이 바로 쌓이지는 않습니다. **동기화**가 필요합니다.

1. **Git 변경 이력** 탭으로 이동한다.
2. 방금 등록한 **장비**를 선택한다.
3. 필요하면 Repository 필터를 고른다. (전체도 가능)
4. **Git 동기화**를 누른다.
5. 완료 메시지(신규 Commit 수 등)를 확인한다.
6. Commit 목록이 보이면 성공이다.

이후 새 커밋이 쌓이면 같은 화면에서 다시 **Git 동기화**를 실행합니다.

---

## 5. 변경내역서 분석 (Web, 권장)

Extension/Web에서 변경내역서와 Git을 잘 연결하려면, 해당 장비의 PPT를
한 번 이상 분석해 두는 것이 좋습니다.

1. **변경내역서 분석** 탭을 연다.
2. 장비를 선택한다.
3. 검색어를 넣거나 분석 실행 절차에 따라 **분석**을 수행한다.
4. 분석이 끝날 때까지 기다린다. (문서 수·네트워크에 따라 수십 초 이상 걸릴 수 있음)
5. 결과 목록·Cache가 보이면 준비된 상태이다.

> 장비·Git·변경내역서가 등록되어 있어도, PPT 분석을 하지 않으면  
> Extension 결과에 변경내역서가 비어 있거나 적을 수 있습니다.

---

## 6. Source Trace 조회 (Web 보조 Client)

IDE Extension을 설치하거나 사용할 수 없는 환경에서는 브라우저의 **Source Trace 조회** 탭으로
동일 Backend 결과를 직접 조회할 수 있습니다.

### 6-1. 함수 변경 이력 조회

1. **Source Trace 조회** 탭을 연다.
2. **함수 변경 이력 조회**를 선택한다.
3. 장비를 선택한다.
4. 필요하면 **소스 파일 경로**를 Git Repository 기준 상대 경로로 입력한다.
5. **함수명**을 입력한다.
6. **변경 이력 조회**를 누른다.
7. 화면 하단의 Markdown 결과를 확인한다.

### 6-2. 선택 코드 변경 근거 조회

1. **Source Trace 조회** 탭에서 **선택 코드 변경 근거 조회**를 선택한다.
2. 장비를 선택한다.
3. Repository가 여러 개면 대상 Repository를 선택한다.
4. **소스 파일 경로**, **시작/종료 Line**, **선택 코드**를 입력한다.
5. 필요하면 **포함 함수명**을 입력한다.
6. **변경 근거 조회**를 누른다.
7. 화면 하단의 Markdown 결과를 확인한다.

### 6-3. 주의사항

- 파일 경로는 **절대경로가 아니라 Git Repository 기준 상대 경로**를 입력한다.
- 선택 코드 조회의 Line 번호는 **1부터 시작**한다.
- 결과는 Web이 다시 분석하지 않고 Backend의 `response.content`를 그대로 표시한다.
- 함수 조회는 현재 API 계약상 Repository 힌트를 직접 받지 않으므로, 다중 Repository 환경에서는
  파일 경로를 함께 입력하는 것이 좋다.

## 7. VS Code Extension 설치

Extension은 **서버가 아닙니다.** 개발자 개인 PC의 VS Code에 설치합니다.  
Node.js / npm 설치는 필요 없습니다.

### 7-1. 파일 준비

`산출물/운영PC/VSCode-Extension/` 폴더에서 다음을 받습니다.

- `source-trace-vscode-*.vsix` (설치 파일)
- 이 매뉴얼 또는 `00_읽어보세요.md` / `참고_README.md`

### 7-2. 설치

**방법 A — 화면에서 설치**

1. VS Code 실행
2. 왼쪽 **Extensions(확장)** 아이콘
3. 오른쪽 위 `...` → **VSIX에서 설치... (Install from VSIX...)**
4. `.vsix` 파일 선택
5. 설치 후 필요하면 **Developer: Reload Window**로 창 새로고침

**방법 B — 명령줄**

```bat
code --install-extension "source-trace-vscode-0.5.5.vsix"
```

(파일명은 폴더에 있는 실제 `.vsix` 이름을 사용합니다.)

이전 버전이 있으면 **최신 `.vsix`로 다시 설치**하세요.

### 7-3. 다른 IDE (선택)

| Client | 설치 파일 |
|---|---|
| Eclipse | `eclipse\source-trace-eclipse-update-site-0.1.1.zip` |
| Visual Studio 2017 | `visualstudio\source-trace-visualstudio2017-0.1.3.vsix` |
| Visual Studio 2010 | `visualstudio\source-trace-visualstudio2010-0.1.3.vsix` |

Visual Studio 2022는 공식 배포 대상이 아닙니다. Continue는 공식 범위가 아닙니다.

## 8. Extension 최초 설정

숫자 장비 ID를 외울 필요는 없습니다. 설정 마법사를 사용하세요.

1. VS Code에서 `F1` (또는 `Ctrl+Shift+P`)
2. **`Source Trace: 서버 및 장비 설정`** 실행
3. 서버 주소 입력  
   - 예: `http://192.168.10.50:8010`  
   - `/api/...` 경로는 붙이지 않는다.
4. 서버 연결 확인이 성공하는지 본다.
5. 목록에서 **장비명**을 선택한다.  
   - 예: `개집표기 (ID 2 · Git 저장소 N개 · 변경내역서 등록됨)`
6. 설정 완료. 재시작 없이 바로 사용할 수 있다.

### 자주 쓰는 명령

| 명령 | 언제 쓰나 |
|------|-----------|
| `Source Trace: 서버 및 장비 설정` | 처음 설정, 서버 주소 변경 (서버 URL 입력 포함) |
| `Source Trace: 장비 변경` | 같은 서버에서 장비만 바꿀 때 (서버 URL을 다시 묻지 않음) |
| `Source Trace: 서버 연결 확인` | 연결만 테스트 |
| `Source Trace: 현재 설정 보기` | 지금 서버·장비 확인 |

참고:

- 서버 주소는 보통 **전역(Global)** 설정
- 장비는 **워크스페이스(Workspace)** 별로 저장되어, 프로젝트마다 다른 장비를 쓸 수 있음
  (예: 프로젝트 A = 휴대용정산기, 프로젝트 B = 개집표기 → 각각 유지)

## 9. Extension으로 변경 이력 조회

용도에 따라 **두 명령 중 하나**를 사용합니다.

```text
함수 전체 변경 흐름을 볼 때
→ Source Trace: 함수 변경 이력 조회

현재 선택한 한 줄·코드 블록의 실제 변경 Commit을 볼 때
→ Source Trace: 선택 코드 변경 근거 조회
```

### 8-1. 함수 변경 이력 조회

1. VS Code에서 장비 소스 파일(`.c`, `.h` 등)을 연다.
2. 조회할 **함수명**을 더블클릭하거나, 관련 코드를 드래그로 선택한다.
3. 편집기에서 **우클릭 → `Source Trace: 함수 변경 이력 조회`**  
   (또는 `F1` → 동일 명령)
4. 질문을 입력한다.  
   - 기본 예: `선택한 코드가 왜 변경됐는지 알려줘`  
   - 예: `이 함수 언제 추가되었어?`
5. 옆에 Untitled Markdown 결과 문서가 열리고 **Markdown Preview가 자동으로 표시**된다.
   (`.md` 파일로 자동 저장하지 않으며, 저장 여부는 사용자가 결정한다.)
6. 진행 상황은 **보기 → 출력(Output) → Source Trace**에서 자동으로 확인할 수 있다
   (분석 시작 시 Output 패널이 자동으로 열립니다).

결과에서 볼 수 있는 내용 (요약):

- **한눈에 보기** — 최초 확인, Git 변경 흐름, 관련 공식 문서 건수, Commit 직접 연결 문서/단계 연결 문서/관련 참고 문서
- **핵심 변경 흐름** — `Git 근거` / `문서 연결` 열 분리 (관련 참고는 Commit 상세·문서 연결 열에 넣지 않음)
- **변경 상세 (Git)** — 초기 개발 및 주요 기능 변경 · 개발 및 보조 변경 · 후속 Git 유지보수 · 연관 Git 이력
- **관련 공식 문서** — 문서별 연결 유형(Commit 직접 근거 / 단계 연결 근거 / 관련 참고). Commit 상세에는 직접·단계만 표시

### 8-2. 선택 코드 변경 근거 조회

특정 한 줄 또는 코드 블록이 **정확히 언제, 어떤 Commit에서** 바뀌었는지 확인할 때 사용합니다.
함수 전체 이력과 달리 키워드 검색이 아니라 `git blame`·line history를 기준으로 동작합니다.

1. 소스 파일에서 확인하고 싶은 코드를 **한 줄 또는 여러 줄 드래그로 선택**한다.
   (선택하지 않으면 실행되지 않고 코드를 선택하라는 안내가 표시됩니다.)
2. 편집기에서 **우클릭 → `Source Trace: 선택 코드 변경 근거 조회`**  
   (또는 `F1` → 동일 명령)
3. 별도 질문 입력 없이 바로 분석이 시작됩니다.
4. 결과 Markdown에는 다음이 표시됩니다.
   - 현재 라인의 `git blame` Commit·작성자·날짜·Commit 메시지
   - 실제 Diff에서 확인된 변경 내용(추가/수정/이동/주변 변경)
   - line history (가능한 경우) — 실패하면 추적 제한 사유를 표시
   - 직접 연결된 공식 문서(없으면 "확인하지 못했습니다"로 표시, 관련 없는 문서를 대신 보여주지 않음)
   - 포함 함수의 전체 이력은 `함수 변경 이력 조회`에서 별도 확인하라는 안내

라인 조회는 코드 이동·대규모 리팩터링·Git history 단절·merge·아직 커밋되지 않은
코드에서는 완전한 이력을 추적하지 못할 수 있으며, 이 경우 결과에 제한 사유가 표시됩니다.

AI(Ollama) 보조 설명은 기본 **꺼져 있습니다.**  
근거 검색 자체는 Git·변경내역서 연결로 동작하며, 결과 Markdown에는 AI 보조 설명
문구를 별도로 표시하지 않습니다(맨 끝에 `조회: YYYY-MM-DD HH:MM`만 표시).

> Web `Source Trace 조회`와 IDE Client는 모두 같은 Backend 공식 결과를 조회하는 경로입니다.
> 별도 AI 채팅 도구 연동은 지원하지 않습니다.

---

## 10. Web에서만 조회하는 경우

Extension 없이 Web만 사용할 수도 있습니다.

| 목적 | 메뉴 |
|------|------|
| Commit·Diff 확인 | Git 변경 이력 |
| 변경내역서 검색·분석 | 변경내역서 분석 |
| 함수/선택 코드 조회 | Source Trace 조회 |
| 장비/경로/Git 관리 | 장비 관리 |

함수를 소스에서 바로 집어 조회하려면 **Extension**이 더 편리합니다.

## 11. 문제 해결

### 웹

| 증상 | 확인할 것 |
|------|-----------|
| 페이지가 안 열림 | 서버 기동 여부, `http://서버IP:8010`, 방화벽/망 구간 |
| 변경내역서 경로 확인 실패 | UNC인지, 공유 권한, 서버 PC에서 해당 경로 접근 가능 여부 |
| Git 연결 실패 | URL/경로, 서버의 Git 계정·Credential, Repository 상태 |
| Commit이 비어 있음 | **Git 변경 이력 → Git 동기화** 실행 여부 |
| 변경내역서가 안 나옴 | 폴더 등록 + **변경내역서 분석** 실행 여부 |

### Extension

| 증상 | 확인할 것 |
|------|-----------|
| 서버 연결 실패 | `서버 및 장비 설정` / `서버 연결 확인`, 서버 IP·포트 |
| 장비 목록 없음 | Web **장비 관리**에 장비가 있는지 |
| 장비 미선택 | `서버 및 장비 설정` 또는 `장비 변경` |
| 선택 코드 없음 | `선택 코드 변경 근거 조회`는 코드를 실제로 드래그 선택한 뒤 다시 실행 |
| line history 확인 제한 | 코드 이동·리팩터링·history 단절 가능성. blame Commit 결과는 유효함 |
| 변경 이력 없음 | 해당 장비 Git 등록·동기화 |
| 변경내역서 없음 | UNC 등록 + Web에서 PPT 분석 |
| 응답이 너무 오래 걸림 | `useOllama`가 켜져 있으면 끄기, 서버 부하 확인 |
